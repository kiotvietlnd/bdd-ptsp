1. MỤC ĐÍCH VÀ PHẠM VI

1.1 Mục đích (Goal)

Quy trình này nhằm:

  • Chuẩn hóa quy trình phát triển sản phẩm SaaS tại KiotViet theo phương pháp BDD (Behavior-Driven Development)
  • Tích hợp AI Agent vào toàn bộ vòng đời phát triển, từ thu thập yêu cầu đến triển khai và cải tiến liên tục
  • Đảm bảo sự đồng bộ giữa yêu cầu nghiệp vụ, đặc tả BDD, code, test và tài liệu qua cơ chế "Living Documentation"
  • Thiết lập Single Source of Truth (SSOT) cho Business Rules
  • Tạo quy trình bàn giao vận hành rõ ràng giữa Development Team và PST

1.2 Phạm vi áp dụng (Scope)

Phạm vi Mô tả
Đối tượng Tất cả các dự án phát triển tính năng mới hoặc cải tiến sản phẩm SaaS tại KiotViet
Giai đoạn Từ Discovery (phát hiện vấn đề/cơ hội) đến Release và Monitoring (triển khai và theo dõi sau ra mắt)
Bộ phận PM, PE, UX/UI Design, Development Team (Dev+QE), Team Lead, DevOps, Vận hành
Loại công việc Phát triển tính năng mới, Cải tiến/tối ưu tính năng hiện có, Giải quyết vấn đề người dùng

2. TỔNG QUAN QUY TRÌNH

2.1 Cấu trúc 3 Phase - 16 Steps

Quy trình phát triển sản phẩm theo BDD được chia thành 3 Phase chính với tổng cộng 16 Steps:

Phase Tên Phase Số Steps Mục tiêu chính
Phase 1 Discovery & Define Solution 5 Steps Xác định vấn đề, định nghĩa giải pháp, tạo BDD scenarios draft
Phase 2 Development & Verification 7 Steps Phát triển code, test, verify và CI/CD
Phase 3 Release & Monitoring 4 Steps UAT, bàn giao, golive và monitoring

2.2 Nguyên tắc xuyên suốt

NGUYÊN TẮC CỐT LÕI:

  1. Business Rules = Single Source of Truth - Mọi quyết định về behavior phải dựa trên Business Rules
  2. No Business rule Final = No Dev - Không có Business rule approved = Không được bắt đầu coding
  3. Single Commit Principle - Docs + Gherkin + Code + Test phải có đầy đủ & được commit cùng lúc
  4. Living Documentation - Tài liệu luôn được cập nhật và đồng bộ với trạng thái thực tế của hệ thống

4. CHI TIẾT 3 PHASE

PHASE 1: DISCOVERY & DEFINE SOLUTION

Mục tiêu: Xác định vấn đề, định nghĩa giải pháp và tạo Gherkin Draft (happy cases) làm nền tảng cho development.

Step Tên Mục tiêu Output chính Owner
Step 1 Identify Problems or Opportunities Xác định vấn đề/cơ hội, Business Objectives, KPIs Problem Statement (Why), Business & Product Objectives, KPIs (optional) PM (A/R), PE (R), UX (R), Dev Team (C), Team Lead (I)
Step 2 Discover and Define Solutions Xây dựng Feature Brief, Business Workflow, Main Business Rules Business Workflow, Feature Brief (feature list + screen list, Main Use Cases, Main Business Rules), Technical Feasibility Review, Dependency List PM (A), PE (A/R), UX (R), Dev Team (C), Team Lead (I)
Step 3 Build and Validate Prototype Xây dựng wireframe/prototype, validate với user (optional) User Flow & Wireframe, Hi-fi and Concept Test Result (optional), Technical Solution (initial concept) PM (A/R), UX (A/R), Designer (R), PE (C), Dev Team (C), Team Lead (I)
Step 4 Solution Design & Define Business Rules Thiết kế giải pháp kỹ thuật high-level, định nghĩa đầy đủ Business Rules, tạo Gherkin Draft (happy cases + AC) Business Rules Document (complete with IDs), Gherkin Draft v0.9 (happy cases + AC, tags: @feature, @happy_case, @draft), High-level Technical Solution proposal PM (A), PE (A/R), Designer (C), Dev Team (C-optional), QE (C-optional), Team Lead (R)
Step 5 Develop UI/UX Design Phát triển Hi-Fi design, align với Business Rules và Gherkin Draft Approved Designs, Updated UX Flow, High-Fidelity UI Designs, Design Specs, UI State Variations PM (A), PE (R), UX (R), Designer (R), Dev Team (C), Team Lead (I)

Lưu ý quan trọng về Step 4:

  • Gherkin Draft chỉ cần đủ để làm rõ business rules (happy cases + AC)
  • Edge cases và exception cases sẽ được bổ sung trong Phase 2
  • Three Amigos Workshop sẽ diễn ra trong Phase 2 (Step 6)
  • Finalize Gherkin sẽ thực hiện trong Phase 2 (Step 7) với sự tham gia của Dev & QE

PHASE 2: DEVELOPMENT & VERIFICATION

Mục tiêu: Phát triển code theo BDD, đảm bảo traceability và quality thông qua testing và CI/CD.

Step Tên Mục tiêu Output chính Owner
Step 6 The 3 Amigos Session & Refinement Phân tích yêu cầu từ Phase 1, T3A session để clarify requirements, xác định scope và priority Checklist tài liệu Phase 1, Meeting notes (T3A), Clarified requirements, Edge cases identified, Refined scope document, Confirmed Technical Solution Team Lead (A) - facilitate, PE (R), Dev (R), QE (R), Tech Lead (C)
Step 7 Gherkin Enrichment Làm giàu Gherkin scenarios với edge cases, error handling, PE approve Gherkin Final Gherkin-{Feature}.feature (PE Approved), Coverage matrix, Approval record PE (A/R), QE (A/R), Dev (R) - cả team phối hợp, Tech Lead (C), Team Lead (I)
Step 8 Code & Test Generation Implement code theo BDD, AI-assisted code gen, viết tests với BR-ID Production code với BR-ID comments, Unit tests (nếu có), Function tests (theo ATDD/TDD), BDD tests, Test results (PASS) Developer (A/R), QE (A/R) - BDD test gen, AI Tool (R)
Step 9 Verify & Refactor Test automation, coverage >80%, QE verify, refactoring decision (legacy code) All tests pass (BDD 100%, Unit, Function), Code coverage report (>80%), QE sign-off, Refactoring plan (nếu cần) Dev (R), QE (A/R), Tech Lead (A)
Step 10 CI/CD & Integration Test Commit docs+code+test (Single Commit), PR review, merge to develop, CI/CD deploy Dev, Integration & Function Test Git commit với traceability, PR approved, Code merged to develop, CI passed, Deployed app on Dev, Integration & Function test results, QE sign-off Dev (A/R), QE (A/R) - Integration & Function Test, DevOps (A/R) - CI/CD monitoring, Peer Developer (R) - PR review
Step 11 Exploratory Testing Kiểm thử khám phá trên Dev environment, AI-assisted charter writing Exploratory Testing Report, Charter, Session recordings, Bug reports (@exploratory_bug), Recommendations for BDD enhancement QE (A/R), AI Tool (C), PE (C), Dev (C)
Step 12 Regression Test & Ready for Live Verify "Stable Enough", tạo Release branch, deploy Staging, Regression test, Go-live & Rollback rehearsal Stable Enough Verification Report, Release branch created, Regression Test Report, Go-live runbook, Rollback runbook, Final sign-off từ QE, Tech Lead, PE, DevOps QE (A/R), Tech Lead (A/R), PE (A/R), DevOps (A/R), Security Team (C)

CRITICAL GATES:

  • Gate 1 (Step 6): T3A session completed với đầy đủ PE, Dev, QE; tất cả câu hỏi đã clarify
  • Gate 2 CRITICAL (Step 7): PE+QE approved Gherkin Final - No Gherkin Final = No Dev
  • Gate 3 (Step 9): QE sampling sign-off
  • Gate 4 (Step 10): CI Pass, QE sign-off (Integration & Function Test)
  • Gate 5 (Step 11): Exploratory testing complete
  • Gate 6 (Step 12): "Stable Enough" verified, Final sign-off

PHASE 3: RELEASE & MONITORING

Mục tiêu: Đảm bảo chất lượng qua UAT, bàn giao cho PST, release và monitoring sau golive.

Step Tên Mục tiêu Output chính Owner
Step 13 UAT Kiểm thử chấp nhận: Exploratory + Gherkin + Design validation UAT Sign-off Document, Bug list QE (A/R), PE (A), Designer (R)
Step 14 Handover to PST Bàn giao documentation, KT session, validation Handover Sign-off, KT recordings, Shadow plan Dev (R), PE (R), PST (A)
Step 15 Golive - Release Deploy production, communication, feature flag management Feature live, Release notes, Rollback plan ready DevOps (R), PE (R), Dev (R)
Step 16 Monitoring System monitoring, alert handling, hypercare, post-launch review, Living docs updated Monitoring reports, Post-launch review, Living docs updated DevOps (R), PST (R), PE (R)

CRITICAL GATES:

  • PE Sign-off (sau Step 13)
  • PST Accept (sau Step 14)
  • Smoke Pass (sau Step 15)

5. QUALITY GATES

5.1 Tổng hợp Quality Gates

Gate Vị trí Điều kiện Pass Blocker nếu Fail
G1 Sau Step 6 (T3A & Refinement) T3A session completed với đầy đủ PE, Dev, QE; Tất cả câu hỏi/ambiguity đã clarify; Scope và priority xác định rõ; Technical solution confirmed Clarify lại với PM/PO, Re-schedule T3A
G2 (CRITICAL) Sau Step 7 (Gherkin Enrichment) Gherkin Final approved by PE+QE; Coverage complete (tất cả BR có Gherkin); Traceability với BR-ID clear BLOCK: No Dev allowed
G3 Sau Step 9 (Verify & Refactor) All tests pass locally; Coverage >80%; QE sampling sign-off; Pass Function Test checklist Fix code/tests, Re-run tests, Get QE re-approval
G4 Sau Step 10 (CI/CD) CI/CD pipeline passed; Integration & Function tests passed on Dev; QE sign-off Fix bugs, Re-deploy, Re-run tests
G5 Sau Step 11 (Exploratory Testing) Session completed; All critical bugs logged; Findings analyzed; No blocker issues Fix critical bugs, Update BDD (nếu cần), Re-test
G6 (CRITICAL) Sau Step 12 (Regression & Ready for Live) Development đạt "Stable Enough"; Release branch tested trên Staging; Regression tests passed (>95%); Final sign-off từ QE, Tech Lead, PE, DevOps BLOCK GO-LIVE until fixed
G7 Sau Step 13 (UAT) UAT Sign-off by PE; No P1/P2 bugs Không được Handover
G8 Sau Step 14 (Handover) PST Accept; KT completed Không được Golive
G9 Sau Step 15 (Golive) Smoke tests pass; No critical errors Rollback nếu fail

5.2 Gate Decision Flow

GATE CHECK | +-------------------+ | | [PASS] [FAIL] | | V V Proceed to [ Identify Root Cause ] Next Step | +---------------+---------------+ | | | [Minor Fix] [Major Issue] [Scope Change] | | | V V V Fix & Retry Loop back to Escalate to Same Step Previous Step PM/Stakeholder

Chú thích:

  • I = Informed (Được thông báo)

7. NGUYÊN TẮC CỐT LÕI

7.1 Business Rules = Single Source of Truth

Business Rules Documents = SSOT | +----+----+ | | | Gherkin Code Test | 100% Traceability
  • Mọi quyết định về behavior phải dựa trên Business Rules
  • Business Rules phải được PE approve
  • Code phải có BR-ID comments
  • Test phải có tên tương ứng với BR-ID

7.2 No Gherkin Final = No Dev

Phase 1 Step 4: Gherkin Draft v0.9 (happy cases) | Phase 2 Step 6: T3A Session | Phase 2 Step 7: Gherkin Enrichment | GATE: Gherkin Final ready (PE+QE Approved)? |-- YES --> Step 8 (Code & Test Gen) |-- NO --> Loop back (refine Gherkin)
  • Đây là Quality Gate quan trọng nhất
  • PE+QE phải approve Gherkin Final trước khi Dev bắt đầu coding
  • Gherkin Draft từ Phase 1 chỉ là bản nháp (happy cases)
  • Gherkin Final từ Phase 2 Step 7 mới là bản hoàn chỉnh (bao gồm edge cases, error handling)

7.3 Single Commit Principle

Git Commit: |-- docs/business-rules/BR-Domain-final.md |-- features/Gherkin-Feature.feature |-- src/Service.java (với BR comments) |-- test/Test.java
  • Docs + Gherkin + Code + Test trong 1 commit
  • Đảm bảo traceability hoàn chỉnh

7.4 Living Documentation

BDD + Business Rules + Code + Tests | Living Documentation | Always in sync
  • Tài liệu luôn được cập nhật cùng code
  • Feedback Loop sau mỗi release

7.5 Progressive Improvement (Legacy Code)

Phase Trạng thái Giá trị
Phase 1 Legacy: Messy code, No docs 0%
Phase 2 Documentation: Docs + Gherkin 70%
Phase 3 Refactored: Clean code + Tests 100%
  • Không cần refactor ngay
  • Docs First, Code Later
  • Chấp nhận messy code nếu đã có documentation
